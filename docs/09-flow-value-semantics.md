# FlowIndex 1.4: типы значений и доказанные преобразования

Дата: 2026-08-07.

## Зачем изменена schema

`SymbolOverview` должен объяснять не только происхождение значения, но и его
контракт: TypeScript-тип, характер результата и преобразование. Эти сведения
нельзя надёжно восстанавливать из названий узлов в React-интерфейсе, поэтому они
материализуются анализатором и сохраняются в canonical `FlowIndex`.

Schema повышена с `1.3.0` до `1.4.0`. После обновления нужен новый `scan`.
Старые `flows.json` считаются несовместимыми и не смешиваются с новым read
model.

## Контракт значения

`FlowNode.valueSemantics` содержит:

```ts
{
  type?: string;
  transformation: {
    kind:
      | "direct"
      | "constant"
      | "property-read"
      | "find"
      | "filter"
      | "map"
      | "reduce"
      | "fallback"
      | "condition"
      | "object"
      | "array"
      | "call"
      | "expression";
    inputPaths: string[];
    expression?: string;
    code?: string;
    operation?: string;
    file?: string;
    line?: number;
    endLine?: number;
    expressionLine?: number;
  };
}
```

- `type` берётся из TypeScript type checker в контексте исходного выражения;
- `kind` определяется по форме AST, а не по имени переменной;
- `inputPaths` сохраняет реально прочитанные локальные пути;
- `expression` сохраняет точный AST-фрагмент без сгенерированного описания;
- `code` сохраняет полную связанную декларацию значения, включая
  многострочный initializer/callback; если отдельной декларации нет,
  используется само выражение;
- `operation` хранит доказанное имя вызова, когда преобразование является
  function/method call;
- `file` и `line` позволяют открыть этот фрагмент в общем source modal.

Роль в `SymbolOverview` выводится из этого контракта и фактических входящих
рёбер: `pass-through`, `derived`, `combined` или `constant`.
Рядом с ролью доступна кнопка «Код»: она показывает полный AST-блок,
относящийся к значению, но не весь исходный файл и не сгенерированный пересказ.
Для импортированной константы TypeScript symbol разрешается до фактической
`const`/enum-декларации: модалка показывает файл и строки определения, а не
только место использования в hook. Если декларация находится вне проекта или
не разрешилась, сохраняется честный fallback на выражение использования.

## Контракт UI-effect

`FlowNode.uiEffect` отдельно хранит семантический вид:

```ts
{
  kind: "conditional-render" | "rendered-value";
  targetName?: string;
}
```

UI локализует этот факт как «Управляет отображением …» или «Выводит значение в
…». Техническое имя узла остаётся в FlowIndex и Evidence, но больше не является
основным пользовательским объяснением.

## Код шага трассы

Для API-узла evidence сохраняет не только отдельный `CallExpression`, а
ближайший законченный statement внутри thunk. Поэтому «Посмотреть код» может
показать целиком присваивание, `return`, request guard или общий
`Promise.all`, в котором участвует вызов. Весь thunk и исходный файл при этом
не подмешиваются в краткую модалку.

`FlowEvidence.line` указывает на точную строку выбранного API-вызова, а
`FlowEvidence.codeStartLine` — на первую строку показанного блока. Это позволяет
правильно пронумеровать фрагмент и подсветить конкретный вызов, даже если один
statement содержит несколько API-источников.

Для шага async operation, построенного из Redux `extraReducers`, применяется
та же граница: сохраняется один полный `addCase` вместе с reducer callback.
Предыдущие и последующие элементы builder-цепочки не попадают в модалку, а
строка lifecycle-ссылки (`operation.fulfilled`/`pending`/`rejected`) остаётся
точкой фокуса.

## Границы

- тип отражает конфигурацию TypeScript сканируемого проекта, включая `any`;
- анализатор классифицирует только известные формы AST и использует общий
  `expression` для остальных;
- назначение доменного значения не выводится из имени и не генерируется;
- сложные mutation и control-flow преобразования не заявляются доказанными без
  отдельного контракта и fixture.
